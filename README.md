# Media Buyer Control Center — مركز إدارة أعمال الميديا باير

تطبيق شخصي خاص لإدارة أعمال الميديا باير: العملاء، الاشتراكات والتجميد، الحملات ومؤشراتها، المتابعة اليومية، المهام، المدفوعات والتحصيل، التقارير السريعة (واتساب + PDF)، عروض الأسعار، التقويم، خزنة الحسابات المشفرة، سجل النشاط، المستخدمون والصلاحيات، والنسخ الاحتياطي.

---

## 1) البنية التقنية (ولماذا)

| الجزء | التقنية | السبب |
|---|---|---|
| الواجهة | PWA (HTML/CSS/JS بدون إطار ولا خطوة بناء) | تُثبَّت على Android كتطبيق مستقل بأيقونتك، سريعة جدًا، عربية RTL، وتعمل على الجوال والتابلت والكمبيوتر |
| الخادم (Backend) | Cloudflare Workers | كل الصلاحيات والأمان مطبقة على الخادم وليس في الواجهة، مجاني تقريبًا، سريع، بدون صيانة سيرفر |
| قاعدة البيانات | Cloudflare D1 (SQLite) | قاعدة بيانات حقيقية **منفصلة تمامًا عن ملفات الكود** |
| الأسرار | Worker Secrets | `SETUP_TOKEN` و `VAULT_KEY` لا تُحفظ في الكود ولا في Git |

```
public/            الواجهة (PWA): صفحات، تصميم، أيقونات، خطوط
worker/            الخادم: API، المصادقة، الصلاحيات، التشفير، النسخ الاحتياطي
migrations/        هيكل قاعدة البيانات
tests/             اختبارات API (46 اختبار) واختبار واجهة بالمتصفح
scripts/           أدوات مساعدة (توليد المفاتيح، الأيقونات)
```

### فصل الكود عن البيانات
- **الكود (Source Code):** هذا المستودع فقط. لا يحتوي أي بيانات عملاء أو كلمات مرور. يمكنك مشاركته مع Claude بأمان.
- **قاعدة البيانات:** في Cloudflare D1 (على الإنترنت)، أو محليًا داخل `.wrangler/` (مستثنى من Git).
- **خزنة الحسابات:** داخل قاعدة البيانات لكن **مشفرة AES-256-GCM** بمفتاح `VAULT_KEY` المحفوظ كسرّ في Cloudflare فقط.
- **النسخ الاحتياطية:** ملفات تنزّلها أنت وتحفظها خارج التطبيق (Drive / بريد / ذاكرة خارجية).

## 2) التشغيل على جهازك (للتجربة أو التطوير)

المتطلبات: Node.js 20+.

```bash
npm install
npm run gen:keys > .dev.vars          # يولّد SETUP_TOKEN و VAULT_KEY محليًا
npm run db:migrate:local              # ينشئ قاعدة البيانات المحلية
npm run dev                           # يفتح على http://localhost:8787
```

افتح `.dev.vars` لترى `SETUP_TOKEN` واستخدمه في شاشة إنشاء حساب المالك.

---

## 3) النشر على الإنترنت (لاستخدامه من جوالك)

مرة واحدة فقط:

```bash
npx wrangler login                                  # تسجيل الدخول لحساب Cloudflare (مجاني)
npx wrangler d1 create mbcc-db                      # انسخ database_id الناتج إلى wrangler.jsonc
npm run gen:keys                                    # يطبع قيمتين — احفظهما في مكان آمن (مدير كلمات مرور)
npx wrangler secret put SETUP_TOKEN                 # الصق قيمة SETUP_TOKEN
npx wrangler secret put VAULT_KEY                   # الصق قيمة VAULT_KEY
npm run deploy                                      # يجمّع ملفات الواجهة، ينشئ الجداول، وينشر التطبيق
```

> ملفات الواجهة (`public/`) تُدمج داخل الـ Worker عبر `npm run build` (يُشغَّل تلقائيًا مع dev/deploy/test)، فالنشر رفعة واحدة.

**النسخة المنشورة حاليًا:** https://media-buyer-control-center.media-buyer-control-center.workers.dev

سيظهر رابط مثل `https://media-buyer-control-center.<اسمك>.workers.dev` — هذا رابط تطبيقك.

> ⚠️ **احفظ `VAULT_KEY` في مكان آمن.** إذا فُقد لا يمكن فك تشفير كلمات المرور المحفوظة في الخزنة (باقي البيانات لا تتأثر). لا تغيّره بعد حفظ بيانات في الخزنة.

---

## 4) إنشاء حساب المالك والدخول

1. افتح رابط التطبيق لأول مرة ← تظهر شاشة **إنشاء حساب المالك**.
2. أدخل `SETUP_TOKEN` + اسمك + اسم مستخدم إنجليزي + كلمة مرور قوية (10 أحرف+).
3. بعد إنشاء المالك **تختفي هذه الشاشة نهائيًا** — لا يوجد تسجيل عام، ولا يستطيع أحد إنشاء حساب بنفسه.
4. (اختياري) من **الإعدادات ← الأمان** فعّل **الدخول بالبصمة** على جوالك.

مجرد تثبيت التطبيق على جهاز آخر لا يعطي أي وصول — البيانات على الخادم ومحمية بتسجيل الدخول والصلاحيات.

## 5) الاستخدام اليومي السريع

- **زر + العائم** (أسفل الشاشة): إضافة عميل، تسجيل دفعة، تقرير سريع، مهمة، حملة، عرض سعر، الخزنة.
- **ابدأ مراجعة اليوم:** يمر على كل العملاء المطلوب مراجعتهم واحدًا تلو الآخر (قائمة نعم/لا، تقييم، ملاحظات، مهام ناتجة).
- **التقرير السريع:** 3 خطوات (البيانات ← الملاحظات ← النتيجة) مع حساب ROAS/CPA/CPC/CTR/CPM تلقائيًا، ثم «نسخ للواتساب» أو «PDF» أو «مشاركة». المسودة تُحفظ تلقائيًا أثناء الكتابة.
- **ملف العميل:** كل شيء في شاشة واحدة بتبويبات + إجراءات سريعة (دفعة، تجميد/فك تجميد، تجديد، تقرير، عرض سعر…).
- **التجميد:** عند فك التجميد تُمدَّد نهاية الاشتراك تلقائيًا بعدد أيام التجميد الفعلية (قابل للتغيير من الإعدادات). يمكن التجميد أكثر من مرة وكل عملية محفوظة في سجل التجميد.
- **الأرشفة:** «نقل إلى العملاء السابقين» لا يحذف أي شيء، ويمكن إعادة التفعيل في أي وقت.

### إضافة العملاء
العملاء ← زر إضافة (أو زر + العائم). يمكن إضافة الاشتراك الأول في نفس النموذج.

### البيانات التجريبية
الإعدادات ← البيانات التجريبية ← «إضافة بيانات تجريبية» (8 عملاء وهميين). كل سجلاتها تبدأ بـ `demo_` وتُحذف بزر «حذف البيانات التجريبية» دون المساس ببياناتك الحقيقية.

## 6) التثبيت على جوال Android

### الطريقة الموصى بها: PWA (بدون متجر)
1. افتح رابط التطبيق في **Chrome** على جوالك وسجّل الدخول.
2. من القائمة (⋮) اختر **«تثبيت التطبيق»** أو **«إضافة إلى الشاشة الرئيسية»** (أو الإعدادات ← التثبيت على الجوال).
3. يظهر التطبيق بأيقونتك واسم «Media Buyer»، ويفتح بشاشة كاملة مع Splash Screen بدون شريط المتصفح.

التحديثات تصل تلقائيًا عند النشر — لا حاجة لإعادة التثبيت.

### إنشاء ملف APK (اختياري)
التطبيق جاهز ليُغلَّف كـ **TWA (Trusted Web Activity)** وهي الطريقة الرسمية من Google:
1. انشر التطبيق أولًا (الخطوة 3).
2. افتح https://www.pwabuilder.com وأدخل رابط تطبيقك ← **Package for stores ← Android** ← Generate. (أو عبر سطر الأوامر: `npx @bubblewrap/cli init --manifest https://رابطك/manifest.webmanifest` ثم `npx @bubblewrap/cli build`).
3. احتفظ بملف مفتاح التوقيع (signing key) الذي يُنشأ — ستحتاجه لكل تحديث للـ APK.
4. لإخفاء شريط العنوان داخل الـ APK: انسخ محتوى `assetlinks.json` الذي يعطيك إياه PWABuilder/Bubblewrap وضعه كمتغير:
   `npx wrangler secret put ASSETLINKS_JSON` (التطبيق يقدّمه تلقائيًا على `/.well-known/assetlinks.json`).
5. انقل ملف `.apk` لجوالك وثبّته (اسمح بالتثبيت من مصادر غير معروفة).

الـ APK مجرد غلاف للتطبيق؛ تحديثات الواجهة تصل تلقائيًا بدون إعادة بناء الـ APK.

## 7) التحديث

بعد أي تعديل على الكود:
```bash
npm test          # اختبارات الخادم
npm run test:ui   # اختبار الواجهة في متصفح (يحفظ صورًا في screenshots/)
npm run deploy    # يطبق أي تغييرات على قاعدة البيانات ثم ينشر
```
إذا أضفت جدولًا أو عمودًا: أنشئ ملفًا جديدًا في `migrations/` (مثل `0002_xxx.sql`) — **لا تعدّل الملفات القديمة**، وخذ نسخة احتياطية قبل النشر.

## 8) النسخ الاحتياطي والاستعادة

**النسخ الاحتياطي** (القائمة ← النسخ الاحتياطي):
- **نسخة عادية:** كل البيانات **بدون** كلمات مرور الخزنة.
- **نسخة مشفرة (موصى بها):** نفس البيانات مشفرة AES-256 بكلمة مرور تختارها.
- **نسخة مشفرة كاملة تشمل الخزنة:** تتطلب فتح الخزنة أولًا، وكلمات المرور فيها لا تُحفظ إلا مشفرة.
- كلمات مرور المستخدمين لا تُضمَّن في أي نسخة إطلاقًا.

احفظ الملف خارج التطبيق (Google Drive، بريدك، فلاش). يُفضّل نسخة أسبوعية.

**الاستعادة:** اختر الملف ← يتم **التحقق من سلامته** (checksum) وفك التشفير ← اختر:
- **دمج آمن:** يضيف السجلات الناقصة فقط ولا يغيّر الموجود.
- **استبدال كامل:** يستبدل البيانات بالنسخة — ويُنزّل تلقائيًا نسخة من بياناتك الحالية قبل التنفيذ.

نسخة إضافية على مستوى الخادم (اختياري): `npx wrangler d1 export mbcc-db --remote --output backup.sql` — وCloudflare D1 يحتفظ أيضًا بإمكانية الاسترجاع لنقطة زمنية (Time Travel) لآخر 30 يومًا.

## 9) الأمان — ما الذي تم تطبيقه

- كلمات المرور مُجزّأة PBKDF2-SHA256 (100,000 دورة) — لا تُخزَّن نصًا أبدًا.
- جلسات بكوكيز `HttpOnly + Secure + SameSite=Strict`، وحماية CSRF، وترويسات أمان (CSP، منع التضمين).
- قفل الحساب 15 دقيقة بعد 5 محاولات دخول خاطئة.
- كل الصلاحيات (24 صلاحية تفصيلية) تُفحص على **الخادم** في كل طلب؛ الموظف بلا صلاحية مالية لا تصله المبالغ أصلًا.
- تعطيل مستخدم أو تغيير كلمة مروره يُنهي جلساته فورًا.
- الخزنة: تشفير AES-256-GCM، تُقفل تلقائيًا (10 دقائق افتراضيًا) وتتطلب إعادة إدخال كلمة المرور، كلمات المرور مخفية افتراضيًا، كل عرض/نسخ يُسجَّل في سجل النشاط **بدون** تسجيل كلمة المرور نفسها، ولا تظهر في التقارير أو التصدير.
- الـ Service Worker لا يخزّن أي بيانات عملاء على الجهاز (فقط ملفات الواجهة).

### نصائح للحفاظ على بياناتك
1. كلمة مرور قوية للمالك + فعّل البصمة.
2. نسخة احتياطية مشفرة أسبوعيًا خارج التطبيق.
3. احفظ `VAULT_KEY` و`SETUP_TOKEN` في مدير كلمات مرور.
4. أعطِ الموظفين أقل صلاحيات ممكنة، وعطّل حساب أي موظف يغادر فورًا.
5. لا تضع ملف `.dev.vars` أو أي نسخة احتياطية داخل المستودع (مستثناة في `.gitignore`).

## 10) تعديل التطبيق مستقبلًا

- الصفحات في `public/js/pages/*.js`، التصميم في `public/css/app.css`، النماذج المشتركة في `public/js/forms.js`.
- الـ API في `worker/routes/*.js`، والصلاحيات وقائمة الأدوار في `public/js/shared.js`.
- لتغيير صورة الهوية داخل التطبيق: الإعدادات ← الهوية والمظهر. لتغيير **أيقونة التثبيت** استبدل الصور في `public/icons/` و`public/img/` (الصور الحالية مقتطعة من الصورة المرجعية — يُفضّل استبدالها بنسخة عالية الدقة من صورتك الأصلية).
- يمكنك إعطاء هذا المستودع لـ Claude بأمان: لا يحتوي أي بيانات أو أسرار.
